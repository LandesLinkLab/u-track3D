Key Design Decisions

Notation: θ, φ = orientation angles, α = angular displacement, s = spatial displacement
Core tracker: trackCloseGapsKalmanSparse — unmodified
Kalman filter: Spatial only (x,y,z); orientation is a constraint
Dipole symmetry: 180° via |cos(angle)|
Bo's insight: √(timeGap) normalization in gap closing
Motion models: Brownian spatial + Brownian rotational

Troubleshooting: Track Over-Segmentation

▶
Problem: The tracking algorithm produces many more track segments than expected (e.g., 95 tracks from 5 emitters). This occurs when molecules undergo photoblinking with dark periods longer than the gap closing window, or when gap closing parameters are too restrictive.

Solution: Relax Gap Closing Parameters

Parameter Original Updated Explanation
gapCloseParam.timeWindow 5 10 Maximum frames to search for gap closing. Increase for longer dark periods.
gapCloseParam.minTrackLen 3 2 Minimum track length to participate in gap closing. Reducing keeps short segments for linking.
maxSearchRadius 1000 nm 2000 nm Maximum spatial distance for gap closing. Increase for faster diffusing molecules.
brownStdMult / linStdMult 3 4 Multiplier for motion standard deviation. Higher values allow more distant links.
timeReachConfB / timeReachConfL 3 / 4 5 / 6 Time window for computing motion statistics. Longer = more reliable velocity estimates.
gapPenalty 1.5 0.5 Penalty per frame of gap. Lower values favor track joining.
wOrient 0.3 0.2 Weight for orientation cost. Reducing makes algorithm less strict on orientation matching.
wOmega 0.5 0.1 Weight for wobble angle cost. Reduce since wobble may fluctuate during dark periods.
maxAngularDist π/3 (60°) π/2 (90°) Maximum angular distance threshold. Increasing allows larger orientation changes.
ConnectSize (post-processing) 3 10 Maximum gap for interpolation. Should match timeWindow to avoid further splitting.
Tip: Start with moderate relaxation and iteratively adjust until track counts match expected values. The diffusion coefficient estimates provide validation—if D values are reasonable, the tracking is likely correct.

Wrapper Architecture: How 6D Costs Integrate with u-track3D

▶
Key Insight: Rather than reimplementing u-track3D's complex LAP framework, our 6D cost functions act as wrappers around the base u-track functions. The wrapper calls the base function to compute spatial costs, then adds orientation costs on top.

Why Use a Wrapper Approach?

Leverages Battle-Tested Code
The base u-track functions handle complex motion prediction, Kalman filtering, sparse matrix construction, and merge/split logic—all validated over 15+ years.
Minimal Maintenance Burden
When u-track3D is updated, only the wrapper interface needs checking—not the entire tracking algorithm.
Clean Separation of Concerns
Spatial tracking stays in u-track3D. Orientation logic is isolated in our wrapper. Easy to debug and extend.

Critical Implementation Detail: Function Signature

⚠️ Common Pitfall The wrapper must have the exact same function signature as the base function. u-track3D passes exactly 10 arguments: 
function [costMat, nonlinkMarker, indxMerge, numMerge, indxSplit, numSplit, errFlag] = ...
    costMat6DSMOLMCloseGaps(trackedFeatInfo, trackedFeatIndx, ...
        trackStartTime, trackEndTime, costMatParam, gapCloseParam, ...
        kalmanFilterInfo, nnDistLinkedFeat, probDim, movieInfo)

% Arguments 1-9: Standard u-track parameters (passed through to base function)
% Argument 10: movieInfo — CRITICAL! Contains our orientation data (theta, phi, omega)

Another Critical Detail: Column Vectors for Motion Multipliers

⚠️ Undocumented Requirement The parameters brownStdMult and linStdMult must be column vectors of length timeWindow, not row vectors or scalars. This is not documented but causes dimension mismatch errors in getSearchRegionRDS.m line 441. 
% WRONG - causes "Dimensions not consistent" error:
'brownStdMult', [3 3 3 3 3], ...    % row vector
'brownStdMult', 3, ...              % scalar

% CORRECT - must be column vector:
'brownStdMult', 3*ones(timeWindow, 1), ...   % [3; 3; 3; 3; 3]
'linStdMult', 3*ones(timeWindow, 1), ...

Diagnostic Output

The wrapper includes diagnostic output to verify it's being called correctly:

  *** costMat6DSMOLMCloseGaps CALLED ***
  [costMat6DSMOLMCloseGaps] Base function returned:
    costMat empty: 0, size: [250 x 250]
    costMat sparse: 1
    errFlag: []
    nonzero entries (potential links): 49

If you see "CALLED" but 0 nonzero entries, the spatial search radius may be too restrictive. If you don't see "CALLED" at all, check that the cost function path is correct in MATLAB.

costMat6DSMOLMLink.m new
Wrapper approach: Calls original u-track function, adds orientation costs.
Total cost: C_total = w_spatial × C_spatial + w_orient × C_orient + w_ω × C_ω Where: C_orient = α² / maxAngDist² (α = angular displacement) C_ω = Δω² / (2π)² (Δω = wobble difference, range [0, 2π] sr) α = arccos(|μ̂₁ · μ̂₂|) ∈ [0, π/2] (with head-tail symmetry) Pseudo-Kalman mode (optional): C_orient = α² / (P_pred + R_meas) P_pred = 2 × D_rot × Δt (expected variance from diffusion) R_meas = σ_CRLB² (measurement variance)

Gap closing with Bo Shuang's √(timeGap) normalization.

estimateDiffusion6D_MLE.m original
Single MLE estimation of D_s and D_α with variable time lags.
MSD equations: Translational: ⟨Δs²⟩ = 2d D_s Δt + 2σ_s² Rotational: ⟨Δα²⟩ = 2 D_α Δt + 2σ_α² MLE(1) closed-form (Bo Shuang Eq. 4): D_s^(1) = (1/(2N·Δt)) · Σ (Δs_i²/n_i) D_α^(1) = (1/(2N·Δt)) · Σ (Δα_i²/n_i) Where: Δs = spatial displacement, Δα = angular displacement n_i = frame count for step i (handles blinking) d = dimensions (3 for translation), N = total steps
estimateDiffusion6D_DualMLE.m new
Dual MLE estimation implementing both methods from Bo Shuang's Langmuir 2013 paper.
MLE(1) — For low-noise data (x < 0.1), Eq. 3-4: L(Δs) = Σ ln{ 1/√(4πD_s·n_i·Δt) · exp(-Δs_i²/(4D_s·n_i·Δt)) } D_s^(1) = (1/(2N·Δt)) · Σ (Δs_i²/n_i) MLE(2) — For noisy data (0.1 < x < 10), Eq. 7-8: L(Δ) = -½ ln|Σ| - ½ Δᵀ Σ⁻¹ Δ (Σ_s)_ij = (2D_s·n_i·Δt + 2σ_s²)·δ_ij - σ_s²·δ_{i,j±1} Where: x = σ²/(D·Δt) is the reduced localization error. Output: D_s_MLE1, D_s_MLE2, D_α_MLE1, D_α_MLE2 + auto-recommendation.
